# 1. Compile-time Polymorphism

## ❓ What is Compile-time Polymorphism?

**Answer**

Compile-time polymorphism (Static Polymorphism) occurs when the method to execute is determined by the Java compiler during compilation.

It is achieved using **method overloading**.

### Example

```java
class Calculator {

    int add(int a, int b){
        return a+b;
    }

    double add(double a,double b){
        return a+b;
    }
}
```

### Advantages
- Faster execution
- Type safety
- Easy readability

---

# 2. Runtime Polymorphism

## ❓ What is Runtime Polymorphism?

**Answer**

Runtime polymorphism (Dynamic Polymorphism) occurs when the JVM decides which overridden method to execute during runtime.

It is achieved using **method overriding**.

### Example

```java
class Animal{
    void sound(){
        System.out.println("Animal");
    }
}

class Dog extends Animal{
    @Override
    void sound(){
        System.out.println("Bark");
    }
}

public class Main{
    public static void main(String[] args){
        Animal a = new Dog();
        a.sound();
    }
}
```

Output

```
Bark
```

# 3. Method Overloading

## ❓ What is Method Overloading?

Methods having the same name but different parameter lists.

Rules:
- Different number of parameters
- Different data types
- Different order of parameters

Return type alone cannot overload a method.

---

# 4. Method Overriding

## ❓ What is Method Overriding?

Child class provides its own implementation of the parent method.

Rules:
- Same signature
- IS-A relationship
- Cannot reduce visibility
- Cannot override final/static/private methods

Example

```java
class Parent{
    void display(){
        System.out.println("Parent");
    }
}

class Child extends Parent{
    @Override
    void display(){
        System.out.println("Child");
    }
}
```

---

# 5. Dynamic Method Dispatch

## ❓ What is Dynamic Method Dispatch?

The process where an overridden method is selected by the JVM at runtime based on the actual object.

```java
Parent p = new Child();
p.display();
```

Reference type → Parent

Object type → Child

Executed method → Child.display()

# 6. Covariant Return Type

## ❓ What is Covariant Return Type?

An overriding method can return a subtype of the original return type.

```java
class Animal{}

class Dog extends Animal{}

class Parent{
    Animal get(){
        return new Animal();
    }
}

class Child extends Parent{
    @Override
    Dog get(){
        return new Dog();
    }
}
```

# 7. Autoboxing

## ❓ What is Autoboxing?

Automatic conversion between primitive types and wrapper classes.

```java
Integer num = 100;
int value = num;
```

Used frequently with overloaded methods and collections.

---

# 8. Varargs

## ❓ What are Varargs?

Allows variable number of arguments.

```java
void print(int... numbers){
    for(int n:numbers){
        System.out.println(n);
    }
}
```

Rules:
- Only one varargs parameter
- Must be the last parameter

---

# 9. Bridge Methods

## ❓ What are Bridge Methods?

Bridge methods are **synthetic methods generated by the Java compiler** to preserve polymorphism when generics and type erasure are involved.

Example

```java
class Parent<T>{
    T get(){ return null; }
}

class Child extends Parent<String>{
    @Override
    String get(){
        return "Hello";
    }
}
```

The compiler generates a hidden bridge method so overridden dispatch still works after type erasure.

# 10. Spring Boot Examples

## Base Service

```java
abstract class BaseService{
    abstract void process();
}

@Service
class UserService extends BaseService{
    @Override
    void process(){
        System.out.println("User");
    }
}
```

## Controller Polymorphism

```java
interface PaymentService{
    void pay();
}

@Service
class CardPayment implements PaymentService{
    public void pay(){}
}

@Service
class UpiPayment implements PaymentService{
    public void pay(){}
}
```

Spring injects implementations through interfaces, demonstrating runtime polymorphism.

# 11. JVM Internals

## ❓ How does JVM implement Runtime Polymorphism?

1. Compiler verifies inheritance.
2. Object stores its actual class metadata.
3. Reference stores declared type.
4. JVM uses virtual method tables (vtable) / dynamic dispatch.
5. Correct overridden method is invoked.

Flow

```
Reference
   │
   ▼
Actual Object
   │
   ▼
Virtual Method Table
   │
   ▼
Correct Method Execution
```

## ❓ Question 1
**What is polymorphism in Java?**

**Answer:**
Polymorphism is the ability of an object to take many forms. In Java it allows the same method call to behave differently depending on the object. It is achieved using method overloading (compile time) and method overriding (runtime).

## ❓ Question 2
**What are the types of polymorphism?**

**Answer:**
Java supports compile-time polymorphism through method overloading and runtime polymorphism through method overriding.

## ❓ Question 3
**What is compile-time polymorphism?**

**Answer:**
The compiler decides which overloaded method to invoke based on the method signature during compilation. It improves readability and performance.

## ❓ Question 4
**What is runtime polymorphism?**

**Answer:**
The JVM selects the overridden method at runtime based on the actual object's type. It is implemented using inheritance and method overriding.

## ❓ Question 5
**Differentiate method overloading and method overriding.**

**Answer:**
- Overloading: same method name, different parameters, resolved at compile time.
- Overriding: same signature in parent and child classes, resolved at runtime.

## ❓ Question 6
**Can constructors be overloaded and overridden?**

**Answer:**
Constructors can be overloaded because they can have different parameter lists. Constructors cannot be overridden because they are not inherited.

## ❓ Question 7
**Why can't static methods be overridden?**

**Answer:**
Static methods belong to the class rather than the object. They are resolved at compile time and are hidden instead of overridden.

## ❓ Question 8
**What is dynamic method dispatch?**

**Answer:**
Dynamic method dispatch is the JVM mechanism that determines which overridden method to execute at runtime based on the actual object.

## ❓ Question 9
**What is covariant return type?**

**Answer:**
An overriding method can return a subclass of the original return type. This feature was introduced in Java 5.

## ❓ Question 10
**Why is @Override recommended?**

**Answer:**
The @Override annotation instructs the compiler to verify that a method actually overrides a superclass method, preventing mistakes.

## ❓ Question 11
**Explain autoboxing with overloaded methods. (Q11)**

**Answer:**
Autoboxing converts primitives to wrapper classes automatically. During overload resolution the compiler considers exact match, widening, boxing, and varargs in that order.

## ❓ Question 12
**How does varargs affect overload resolution? (Q12)**

**Answer:**
Varargs allow a variable number of arguments. Exact overloads are preferred over varargs because they are more specific.

## ❓ Question 13
**What are bridge methods and why are they generated? (Q13)**

**Answer:**
Bridge methods are compiler-generated synthetic methods that preserve polymorphism after generic type erasure.

## ❓ Question 14
**Explain type erasure and polymorphism. (Q14)**

**Answer:**
Type erasure removes generic type information at compile time. The compiler generates bridge methods when necessary to maintain overriding.

## ❓ Question 15
**What is upcasting? (Q15)**

**Answer:**
Upcasting means assigning a child object to a parent reference. It is safe and enables runtime polymorphism.

## ❓ Question 16
**What is downcasting? (Q16)**

**Answer:**
Downcasting converts a parent reference back to a child reference. It requires an explicit cast and may throw ClassCastException.

## ❓ Question 17
**Why use instanceof before downcasting? (Q17)**

**Answer:**
Using instanceof ensures the object is of the expected type before downcasting, avoiding ClassCastException.

## ❓ Question 18
**Can private methods be overridden? (Q18)**

**Answer:**
Private methods are not inherited, so they cannot be overridden. A method with the same name in the child is a new method.

## ❓ Question 19
**Can final methods participate in polymorphism? (Q19)**

**Answer:**
Final methods cannot be overridden, preventing runtime polymorphism for those methods.
